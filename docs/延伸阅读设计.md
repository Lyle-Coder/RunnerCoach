# 延伸阅读（IKUZU5）设计

> 目标：单次训练报告看完后，再多给一两块「值得看两眼」的内容——名词科普、近期赛事、跑者档案。
> 不参与训练判断，不影响报告生成速度，没有网络也要能看。

## 一、放在哪、放多少

**只放 `/view` 报告页**（教练点评之后、「最近活动」之前），**不进一图流 PNG**。

理由：一图流是分享给人的静态图，高度固定 1080×1920，塞阅读内容会挤掉数据；报告页是给自己看的，多两段不算负担。

结构（自上而下）：

```
[教练点评]（已有，AI/人工）
[延伸阅读]          ← 新增
  · 术语卡：TSB 是什么（和这次训练的关系）
  · 轮换卡：赛事 / 跑者 二选一
[最近活动]（已有）
```

- 每次**最多 2 条**：1 条术语 + 1 条（赛事或跑者），由日期决定。
- 术语卡 80~150 字；轮换卡 60~120 字。整块高度控制在 ~220px，不给长报告再加一屏。
- 整块可以关：`config.json` 里 `reading_off = true` 就不渲染（「我的」页后续加开关）。

## 二、数据层

### 文件与优先级

```
garmin_cn/content/terms.json      随包发布（基线内容）
garmin_cn/content/races.json
garmin_cn/content/athletes.json
data/content/*.json               可选覆盖（用户/运维更新，不用发版）
```

读取顺序：`data/content/` > 包内。覆盖文件**整体替换**对应文件，不做逐条合并——合并规则越复杂，出错越难解释。

### 结构（三个文件同一套外壳）

```jsonc
{
  "version": 3,                 // 内容版本，自己递增
  "updated": "2026-11-13",      // 人工最后校对日期
  "items": [ ... ]
}
```

**terms.json**

```jsonc
{"id": "tsb", "term": "TSB（训练压力平衡）",
 "body": "CTL 减 ATL：正数说明比长期水平更「新鲜」，负数说明疲劳在累积……",
 "rel": ["tsb", "ctl", "atl"],       // 与哪些报告指标相关，用于优先命中
 "tags": ["负荷"]}
```

`rel` 是这块能不能「不像随机冷知识」的关键：报告里有 TSB，就优先推和 TSB 相关的术语。

**races.json**

```jsonc
{"id": "qinling-2026", "name": "秦岭山地马拉松 43K",
 "date": "2026-11-29", "dist_km": 43, "ascent_m": 2600,
 "place": "陕西 · 西安", "url": "https://…", "note": "报名已截止，可看直播"}
```

过期规则：只显示 `date >= 今天` 的；全部过期时不出这块，并给一行「赛事清单更新于 2026-11-13」。
`updated` 超过 90 天且当前无未来赛事 → 显示「清单可能已过期」的小字。

**athletes.json**

```jsonc
{"id": "kilian", "name": "Kilian Jornet", "country": "西班牙",
 "bio": "越野跑与天空跑的代表人物，四次 UTMB 冠军……",
 "pb": [{"distance": "UTMB", "result": "19:44:30", "race": "UTMB 2011", "year": 2011}],
 "quote": {"text": "……", "source": "《Summit of My Life》/ 2014 采访"}}
```

规则：`pb` 必须有 `race` + `year`（最好成绩最容易编，没有出处的宁可不写）；`quote.source` 必填，只存短句 + 出处。

## 三、选哪条：确定性轮换

不用随机数（同一份报告刷新两次会变），用日期做种子：

```python
ordinal = date.toordinal()
idx = (ordinal + salt) % len(pool)      # salt 按分类固定
```

- 同一天同一分类永远是同一条；连续 N 天（N = 条目数）不重复；
- **术语优先按 `rel` 过滤**：报告里出现 ACWR/TSB/触地/垂直振幅时，先从相关条目里选；相关条目为空再退回全量轮换，保证不会因为过滤而空着；
- 轮换卡：赛事按「最近一场」直接取，不看轮换；没有赛事才退到跑者轮换（这样赛事永远优先，因为它有截止日期）。

## 四、渲染与降级

新模块 `garmin_cn/reading.py`，只做三件事：

```python
def terms_block(metrics: dict, date: dt.date) -> str
def races_block(date: dt.date) -> str
def athletes_block(date: dt.date) -> str
def block(res: dict) -> str      # 组装；任何异常返回 ""
```

- **纯静态 HTML**，不依赖 JS，不调用模型，不联网；
- 任何异常（文件缺失、JSON 坏了、字段不全）→ 返回空串，报告照常出；
- `reading_off` 为真 → 直接返回空串；
- 卡片样式沿用报告的 `.card` / `.kv`，不新增主题变量。

report.py 里只加一行：`{reading_html}`，位置在教练点评之后。

## 五、内容规范（写内容的人只需要记这几条）

| 项目 | 规则 |
|---|---|
| 术语 | 80~150 字，必须有一句「和你这次的关系」；不写「众所周知」 |
| 赛事 | 必须有日期、距离；报名状态写清；查不到官方链接就不写链接 |
| 跑者 | PB 必须带赛事与年份；名言必须带出处；不写未经证实的传闻 |
| 通用 | 不出现「据说」「网上说」；宁缺毋滥，条数少比写错强 |

## 六、验收与测试（selftest）

1. 结构校验：三个文件逐条字段齐全、`id` 唯一、字数在范围内、`pb` 有 `race`/`year`、`quote.source` 非空、`date` 可解析；
2. 轮换：同一天调两次结果一致；连续 7 天不重复（条目数 ≥ 7 时）；
3. 相关命中：给一个含 `acwr` 的报告指标，返回的术语 `rel` 里应包含 `acwr`；
4. 降级：文件缺失 / JSON 损坏 / `reading_off` → 返回 `""`，报告页仍能完整渲染；
5. 过期：全部赛事过期时不出现赛事卡；`updated` 超 90 天时出现提示文案；
6. 尺寸：两个卡片都出现时，报告 HTML 增量 < 4KB。

## 七、分阶段

| 阶段 | 内容 | 说明 |
|---|---|---|
| M1 | terms + reading.py + 报告插入 + 测试 | 先把「和训练相关」这件事做对 |
| M2 | races（含过期提示） | 需要人工维护一份赛事清单 |
| M3 | athletes（PB + 名言） | 同上，最容易写错，必须带出处 |
| M4 | `data/content/` 覆盖 + 「我的」页只读展示内容版本 | 不用发版也能更新内容 |

M1 单独就有价值：报告里第一次出现「这个指标是什么」的解释。

## 八、风险与取舍

- **内容准确性**是主要风险。名言和 PB 一旦写错很难被发现 → 强制出处字段 + 人工校对，不用模型现生成。
- **报告变长**：控制条数与字数；若仍嫌长，M4 再加「不感兴趣」开关（`reading_off`）。
- **赛事时效**：清单必然过期 → 不给「即将开始」的强承诺，只写日期 + 过期提示。
- **包体积**：三个 JSON 预计 < 30KB，可忽略。
- **不做**：个性化推荐、联网抓赛事、把阅读内容喂给模型（会把幻觉带进点评）。

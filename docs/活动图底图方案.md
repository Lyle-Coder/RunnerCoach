# 活动图底图：手机端接入方案

> 结论：底图实现本来就有（`basemap.py` 高德静态图 + `actcard._track_on_map`），
> **缺的只是手机端这一段**。断点不在绘图，在于图片地址：桌面用 `file://`，
> WebView 里的 `http://` 页面加载不了，于是手机端一直退化成纯 SVG 轨迹。

## 一、现状

| 场景 | 入口 | 底图 |
|---|---|---|
| 桌面 / CLI 出图 | `actcard.render()` | ✅ 有：`basemap.ensure()` → `file:///…png` |
| 手机 App 出图 | `appapi.act_card_html()` | ❌ 无：`build_html(..., basemap=None)` |

`appapi.act_card_html()` 的注释写得很直白：

> 也不取高德底图（`file://` 图片在 http 页面里加载不了，而且离线优先）。

也就是说这是当时的有意取舍，不是遗漏。

## 二、为什么 `file://` 不行

App 的 WebView 加载的是 `http://127.0.0.1:<port>/act-xxx.html`。页面里的
`<image href="file:///data/.../basemaps/xxx.png">` 属于跨协议读取本地文件，
WebView 默认拒绝（`allowFileAccess=false`，这是安全必需）。所以叠图那一层
是空的，代码静默回落到矢量轨迹。

## 三、方案：把底图改成同源 HTTP 资源

一句话：HTML 还是同一个 HTML，只把图片地址从 `file://…` 换成 `/basemap/<file>.png`，
由本机服务提供。

```
App 点活动行
  └─ appapi.act_card_html(id)
       ├─ basemap.ensure(track, 422, 225, aid)       # 命中缓存则 0 请求
       │     └─ 未命中：高德静态图 API → data/basemaps/<aid>-422x225.png
       ├─ build_html(..., basemap={"png": "/basemap/<aid>-422x225.png", "meta": meta})
       └─ 写 output/act-<date>-<aid>.html
WebView 打开该 HTML
  └─ GET /basemap/<aid>-422x225.png  → 200 image/png（本机服务直出文件）
```

叠图的投影仍走 `basemap.fit()` 的固定取景 + `meta`，几何口径和桌面完全一致，
所以**同一张图在电脑和手机上叠出来的轨迹位置一致**。

## 四、改动点

### 1. `garmin_cn/basemap.py`：数据目录改用 `GARMIN_HOME`

现在 `ROOT = Path(__file__).resolve().parent.parent`。APK 里代码在 Chaquopy 的
只读 assets，这会把 `CONF` / `CACHE` 指到 assets 内部，读不到也写不进。
与 `plan.attach()` 踩过的是同一个坑。

```python
def _home() -> Path:
    env = os.environ.get("GARMIN_HOME")
    return Path(env).expanduser() if env else Path(__file__).resolve().parent.parent

ROOT = _home()
```

### 2. `garmin_cn/serve.py`：新增 `/basemap/<name>.png` 路由

放在分享门禁之后、页面路由之前；只认 `[A-Za-z0-9._-]+\.png`，并且 `resolve()`
后再校验一次是否仍在 `basemaps/` 下，防路径穿越。图片给 30 天强缓存——
文件名里带尺寸与版本，内容不会变，没必要每次重下。

### 3. `garmin_cn/appapi.py`：出图时带上底图

```python
bm = None
if mode == PV.MODE_NONE and os.environ.get("GARMIN_MAP", "1") != "0":
    from . import basemap as BM
    got = BM.ensure(detail.get("track") or [], TRK_CW, TRK_CH, aid)
    if got:
        bm = {"png": f"/basemap/{Path(got['png']).name}", "meta": got["meta"]}
html = build_html(row, detail, None, bm, title, privacy=mode)
```

三条硬约束不变：

* `hide` 档**完全不取底图**；`trim` 档用**裁剪后**的轨迹取景，起终点区域不入图；
* 没有 Key / 断网 / 接口失败 → `ensure()` 返回 `None`，静默回落矢量轨迹；
* 缓存键带档位后缀（`<aid>-trim-422x225.png`），不同档位不会混用同一张底图。

注意：`actcard.build_html()` 内部还有一层「非原图档就清空底图」的兜底，
只放行外层不够——`hide` 才清，`trim` 必须保留（这是踩过的坑）。

### 4. Key 的配置入口（App 内）

桌面已有 `data/amap.json`，但手机是独立的数据目录，必须能自己配：

* 「我的」页加一行「地图底图 · 已配置 / 未配置」，点开原生对话框输入高德
  **Web 服务 Key**；
* 保存走 `appapi.set_amap_key(key)` → 写 `GARMIN_HOME/data/amap.json`（0600），
  并顺手调一次 `basemap.probe()` 验证 Key 是否可用（1 次配额）；
* 对话框里写明：配了之后活动图带底图，**轨迹中心点会发给高德**；不配就用矢量轨迹。

## 五、隐私与合规

* 高德属于合规白名单（腾讯 / 高德 / 百度 / 天地图），静态底图由高德官方出图，
  国界、台湾、南海诸岛等要素由数据源负责，我们只叠自己的轨迹。
* **不预置任何 Key**，必须使用者自己申请、自己填；填之前默认关闭。
* 底图 PNG 只落本机 `data/basemaps/`，不上传、不转发；图上的
  「地图数据 © 高德地图」不裁掉（`_track_on_map` 已处理）。
* `hide` 档与底图互斥（完全隐藏轨迹时不取图）；`trim` 档只用中间段取景。

## 六、验证清单

1. **无 Key**：手机出图仍正常，轨迹为矢量，不报错、不空白。
2. **有 Key**：`/basemap/<file>.png` 返回 200、`Content-Type: image/png`、
   字节以 `\x89PNG` 开头；HTML 里 `<image href="/basemap/...">` 能命中。
3. **缓存**：同一活动第二次出图 0 请求（`basemaps/` 命中）。
4. **脱敏**：`privacy=trim/hide` 的产物里不出现 `/basemap/`。
5. **路径穿越**：`/basemap/../../config.json` 返回 404。
6. **画幅**：底图尺寸与 `TRK_CW×TRK_CH` 一致（422×225），叠加后轨迹不偏移。

## 七、工作量

| 改动 | 规模 |
|---|---|
| `basemap.py` 数据目录 | ~6 行 |
| `serve.py` 底图路由 | ~20 行 |
| `appapi.act_card_html` 接底图 + `set_amap_key` | ~30 行 |
| 「我的」页入口 + 原生对话框 | ~70 行 |
| 自检断言 | ~10 行 |

总计约 130 行，不新增依赖、不改出图版式。

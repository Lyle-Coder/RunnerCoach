## 0. 一句话

保留深空底、品牌蓝青和跑道徽标，**收敛装饰**（一页只留一处发光）、**固定阶梯**（8 档字号 / 4 档圆角 / 4pt 栅格）、**组件单一来源**（页面里不出现裸色值和魔法数字）。

这份规范取代 `docs/交互树.md` 第五节「视觉规范」的配色与圆角细则；那一节保留作为历史记录，冲突时以本文为准。

## 1. 为什么改

技术指标全部达标（`tools/audit_ui.py`：360/390/430 三档无溢出、无 <11px 文字、可点元素 ≥40px、对比度全过 AA），问题**纯粹在视觉体系**：

| 问题 | 实测 | 后果 |
| --- | --- | --- |
| 字号碎片化 | `ui.py` 18 档（11、11.5、12、12.5、13、13.5、14 … 46）；11–14px 挤了 8 档 | 相邻两档肉眼分不出，层级靠猜 |
| 圆角碎片化 | 仅 `ui.py` 就 11 档（2/3/8/9/10/11/12/14/16/99/999） | 卡片、行、图标各走一套，像不同人拼的 |
| 卡片底色 5 套 | `.card` `.row` `.vital` `.act` `.plan-hero` 各写一套渐变 | 几乎同色、边缘亮度不同，看起来"脏" |
| 描边 + 辉光过载 | 每个卡片都带蓝色 1px 边和 glow | 整页像线框图，焦点被稀释 |
| 信息缺陷 | 计划页周次竖排折行；历史页 12 个月里 7 个月是 0 次空行 | 不是审美问题，是可读性问题 |

结论：**不是加装饰，而是减装饰 + 立规矩。**

## 2. 四条原则

**P1 一屏一个焦点。** 每页只允许一个发光面、一处彩色主视觉。今日页的焦点是「今天该怎么练」这个结论，不是负荷数字。其余信息靠字重、字号、留白分层。

**P2 数据优先于装饰。** 先定层级：结论 → 关键数值 → 明细。每个数值必须带单位和口径，说明最多两行；口径解释统一放到「延伸阅读」，不塞进数据卡。

**P3 收敛但不平淡。** 深色界面靠三样东西建立层次：三级面色、1px 发丝线、克制的字阶。去掉满屏蓝边后，留白和字重才有分量。

**P4 一套 token 说话。** 颜色、字号、间距、圆角只有四类 token。评审只对 token，不对像素。

## 3. Token

### 3.1 色彩

底色 4 级 + 文字 3 级 + 语义 6 色。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#070B12` | 页面底。不用纯黑，留一点蓝 |
| `--surface` | `#0D141F` | 卡片、列表行（e1） |
| `--surface-2` | `#111B29` | 抬升面、选中行、图标底座 |
| `--surface-3` | `#16233A` | 分段控件选中块、控件槽 |
| `--line` | `rgba(255,255,255,.065)` | 发丝线。**用白透明，不用蓝** |
| `--line-brand` | `rgba(96,165,250,.22)` | 仅 hero 与选中态描边 |
| `--ink` | `#E9F0F8` | 标题、数值、正文主句 |
| `--ink-2` | `#A6B8CD` | 次级标题、可点正文 |
| `--ink-3` | `#7A8DA4` | 说明、单位、坐标轴（仍 ≥4.5:1） |
| `--brand` | `#3B82F6` | 主按钮、当前选中、数据强调 |
| `--brand-soft` | `rgba(59,130,246,.12)` | 标签底、提示条底 |
| `--brand-ink` | `#9CC6FF` | 深色底上的品牌色文字 |
| `--cyan` | `#22D3EE` | 辅助光、渐变终点、kicker |
| `--ok` | `#3FD39A` | 达成、已完成、恢复良好 |
| `--warn` | `#F5A524` | 逾期、注意、负荷偏高 |
| `--bad` | `#F2555A` | 异常、失败、超限 |
| `--ink-inv` | `#F2F7FF` | 实心按钮上的文字 |

对比度实测（卡片底 `#0D141F` / 页面底 `#070B12`）：

| 前景 | 卡片底 | 页面底 |
| --- | --- | --- |
| `--ink` #E9F0F8 | 16.08 | 17.16 |
| `--ink-2` #A6B8CD | 9.11 | 9.72 |
| `--ink-3` #7A8DA4 | 5.43 | 5.79 |
| `--brand-ink` #9CC6FF | 10.50 | 11.20 |
| `--ok` #3FD39A | 9.67 | 10.32 |
| `--warn` #F5A524 | 9.05 | 9.66 |
| `--bad` #F2555A | 5.47 | 5.84 |
| `#66A0FF`（链接/次级强调） | 7.07 | 7.54 |

用色规则：

1. 主色只做三件事：关键动作、当前选中、数据强调；不做大面积背景。
2. 发光只给 hero（一页一处）。普通卡片只用 1px 发丝线 + e1 阴影。
3. 状态色不混用：绿=达成、琥珀=注意、红=异常。不用红色做品牌强调。
4. 图表用同一色相的不同透明度；需要分类时才用运动色（跑/骑/力/游）。
5. 文字只用 ink / ink-2 / ink-3 三级，不叠半透明白。
6. **禁止渐变文字。** 大数字用实色 + 负字距。

### 3.2 字阶

8 档，一档一职责，相邻至少差 2px。

| Token | 字号 / 字重 | 用途 |
| --- | --- | --- |
| `--fs-dsp` | 32 / 600 | 主视觉数字，一屏最多 1 个 |
| `--fs-h1` | 24 / 600 | 页面标题，每页唯一 |
| `--fs-h2` | 20 / 600 | 区块结论、今日判断、卡片主数值 |
| `--fs-title` | 16 / 600 | 卡片标题、列表主行、课次名称 |
| `--fs-lead` | 15 / 400 | 引导句、长文正文 |
| `--fs-body` | 14 / 400–600 | 正文默认；主句 600，说明 400 + ink-3 |
| `--fs-cap` | 12 / 400 | 副标题、按钮、标签、说明 |
| `--fs-micro` | 11 / 400–600 | 下限。标签、单位、坐标轴、时间戳 |

规则：

- 中文 `letter-spacing: 0`；只有英文 kicker 用 `.16em`。
- 所有数字 `font-variant-numeric: tabular-nums`。
- 中文与数字间留一个空格：`6.5 h`、`11.01 km`、`28 天`。
- 只用 400 / 500 / 600 三个字重，不用 650 / 700。

### 3.3 间距与圆角

- 4pt 栅格：`4 / 8 / 12 / 16 / 20 / 24 / 32`。
- 卡片内边距 16；列表行上下 12，行高 64；区块间距 32；页脚前 32。
- 圆角只用 4 档：`--r-1 10`（图标/输入）、`--r-2 14`（行/小卡）、`--r-3 18`（卡片）、`--r-pill 999`（胶囊）。
- 能用留白分层就不加边框；必须加时只有 1px。

### 3.4 阴影

- `--e1`：普通卡片。黑色浅投影 + 1px 发丝线。`0 1px 0 rgba(255,255,255,.03)` 内高光可选。
- `--e2`：hero。品牌描边 + `0 20px 44px -28px rgba(59,130,246,.45)`。**一页一处。**
- 动效 140–200ms，只动 `opacity` / `transform`，不动 `box-shadow`（WebView 重绘）。

## 4. 组件

只允许这些形态。新页面从这里复制，不再自创。下列尺寸以 390 宽为基准。

### 4.1 页头 `page()`

- 结构：kicker（11，`--cyan`，`.16em`，全大写英文）→ h1（24/600，`-0.02em`）→ 导语（12，`--ink-3`，最多一行）→ meta chips（12）。
- kicker **不加 `text-shadow`**：11px 的字挂 12px 高斯模糊，在暗底上糊成一团青雾，
  读出来是「亮」不是「清楚」。页面背景也只留一层极淡冷色渐晕（`.09`），
  不要叠第二层青色——那一层会和页面里唯一那个发光卡抢焦点。
- 上方留白 20；页头下**不画线**，靠 20 空隙分隔。
  曾有一条「蓝→青→透明」的 1px 渐变收尾线，但页头下面紧接的就是带边框的
  卡片，两条线相距 19px、长短不一，看着像没对齐的分隔符。参考稿也没有这条线。
- 一页只有一个 h1。不要在页头放返回按钮之外的第二排操作。

### 4.2 区块头 `sec()`

- 左侧 **3px 纯 `--brand` 竖条**（16px 高，圆角 2）+ 标题 **16/600 `--ink`**；右侧可选 `更多 →`（14，`--brand-ink`）。
- 区块头上间距 **32**，下间距 10。全站只有这一个区块间距：曾经 24 / 40 / 48
  三种混用，同一屏三种节奏，看着「说不出的不整齐」。
- 区块正文（`.flat`）左缩进 11px，与标题**文字**对齐——标题前有 3px 竖条 + 8px 间距，
  正文不缩进会比标题明显靠左，像没对齐。
- 标题**高于**正文一档，作为区块的入口标记；但一页最多 6 个区块，再多就退回过期分组。
- 竖条不要渐变、不要外发光：一屏六七个区块，每条都发光会把 hero 的焦点稀释掉。

### 4.3 卡片

- 普通：`--surface` + 1px `--line` + `--r-3` + 16 内边距 + `--e1`。
- hero：`--e2`，带 `--line-brand`，最多一个，用于「今日结论 / 计划今日 / 关键一次」。
- 卡内标题 16/600；主数值 20/600 或 32/600；说明 12 `--ink-3`。
- 卡片之间间距 12；不同组的卡片之间 24。
- 禁止：每张卡都加发光、每张卡都用渐变底、卡里再套卡。

### 4.4 统计条 `strip` / `vital`

- 三格一张卡，格间 1px 发丝线；每格：标签 11 `--ink-3` → 数值 20/600（单位 12 `--ink-3`）→ 口径 11 `--ink-3`。
- 数值单位与数字之间 5px，不粘连。
- 竖向 `vital` 用于「身体数据」2×2，`--surface-2` 底，圆角 `--r-2`。

### 4.5 标签与胶囊 `chip` / `pill`

- chip：高 26，左右 10，圆角 999，12px，`--surface-2` 底 + `--line` 边；数字用 600。
- 状态 pill：高 26，左右 10，11/600，圆角 999。五种色调，**只换色不换形**：
  - `brand` 品牌实心（白字）——只给「今天」这类唯一的当前项，一屏最多一个
  - `ok` 绿字绿底软（已完成）
  - `run` 品牌蓝字淡底（进行中 / 待完成 / 尚有余量）
  - `warn` 琥珀字淡底（逾期 / 临近）
  - `bad` 红字淡底（未完成）
  - `mute` 虚线灰边（计划外、跳过这类「有这件事但不算计划内」）
  - `ghost` 中性灰边（今日建议、筛选条件这类并列选项，**不是状态**）
- 一个 chip 里最多 5 个字 + 1 个数字。不要做成按钮。

### 4.6 按钮 `btn`

- 高 44（列表内 40），圆角 `--r-1`（10），14/600，左右 18。
- 主按钮：`--brand` 实心 + `--ink-inv` 字，一屏最多 1 个。
- 次按钮：透明底 + `--line` 边 + `--ink-2` 字。
- 危险动作不用红色实心，改用 `--bad` 文字 + 二次确认。

### 4.7 列表行 `row`

- 高 64；图标 34×34 `--surface-2` 圆角 `--r-1`；主行 14/600；副行 12 `--ink-3`；右侧 `›` 12 `--ink-3`。
- 选中态：`--surface-2` 底 + 左侧 2px `--brand` 条。
- 行与行之间不画线，用 12 间距；同组内需要分隔时用 1px `--line`。

### 4.8 周课表行 `wrow`

> 这是本次修掉的排版 bug：日期列原来只有 40px，导致「周二」「力量」竖排、与卡片重叠。

- 网格：`56px | 1fr | auto`，列间距 12。
- 日期列：周几 14/600（`--ink`）+ 日期 11 `--ink-3`，两行固定高，不换行。
- 内容列：课名 16/600；同日多课次时每行一条（`力量 A · 臀腿` / `11 km @ E`），不合并成一行；实练数据 12 `--ink-3`。
- 状态贴最右：已完成/今天/待完成/计划外。
- 行高自适应，最小 64；今天行**整行**用 `--line-brand` 描边 + `--surface-2` 底。
  原来是左侧 3px 条：一条竖线在整行里太弱，扫一眼分不出哪行是今天。
- 日期列右侧一道 1px `--line` 竖线，把「周四 / 11-20」和课名分开；
  不画的话两列会读成一句话。

### 4.9 图表

- 柱：同色系（`--brand` 0.45–0.85），当天高亮；零值画 2px 虚线基线，不画 0 高柱。
- 进度条：高 3，槽 `rgba(255,255,255,.06)`，填充品牌渐变。
- sparkline：1.5px 线，`--brand` 0.5；只做趋势，不加坐标轴。

### 4.10 折叠与空状态

- 连续空月份合并成一行：「2025-12 – 2026-06 · 7 个月无记录」，虚线边、44 高、可展开。
- 单个空月份直接不渲染。
- 空状态文案 12 `--ink-3`，最多两行，不放插画。

## 5. 页面结构

### 今日

`页头` → `hero：结论 + 恢复度环` → `负荷三格` → `身体数据 2×2` → `今日课表` → `赛事提醒` → `最近活动` → `延伸阅读`。

- 首屏必须能回答「今天练不练、练多少」。
- 恢复度环只在 hero 里出现一次；负荷、HRV 等数值不再各自配环。

### 计划

`页头（含 2/6 完成、共 19 周）` → `今日课次 hero` → `本周课表（7 行）` → `进度条` → `计划信息 kv` → `三个操作按钮`。

- 周课表是页面主体，任何筛选/说明都不能插在它与页头之间。
- 计划信息用 kv 列表（来源 / 覆盖 / 完成 / 休息 / 计划外），不用标签堆。

### 历史

`页头（累计口径）` → `本月/本年/累计 三格` → `分段控件（按月/按周/按年/列表 + 运动类型）` → `30 日柱状图` → `有数据的月行` → `折叠的空月份`。



### 小组

`页头（GROUP / 组名 / 人数·身份 / chips）` → `核心数据卡（我·第N名 + 分数 + 口径 + 称号 / 六件衫徽章）`
→ `三个功能图标（Bingo / 足迹 / 远征）` → `目标入口行` → `结对 / 预言` → `本周榜` → `赛事` → `大家的动态`。

- 首屏必须同时看到「我第几、多少分」和榜单；这两件都不能被表单或说明压下去。
- **页头标题 24（`--fs-h1`），卡片主数字 32（`--fs-dsp`）**：两者同 32 时，
  「组名」和「75」在视觉上同级，第一眼不知道该看谁。一屏只有一个 32 的数字。
- 分数下面必须有**口径行**（12，`--ink-3`）：`综合分 · 满分 90（跑量·出勤·爬升·
  进步·连跑）+ 加分 10`。满分与加分上限取服务端 `season.base_max / bonus_max`，
  权重不写进客户端——否则服务端调权重，页面上的说法就成了假的。
- 六件衫用 **6 枚 28px 圆徽章**，不要用「衫名·榜名·得主」的文字行：
  六件全写出来是两行密不透风的字，而且每件衫的颜色在文字里看不出来。
  得主信息放徽章的 `title` 和「六件衫」榜单页。
  **没得到的是空心**（1px 虚线、`rgba(255,255,255,.22)`、透明底），
  得到的是实色 + 2px 同色外环。不要用「同色压到 38% 透明度」表示未获得：
  深底上那等于一个黑点，用户数不出「一共几件、我有几件」，入口右侧
  必须写清 `六件衫 1/6 ›`。
- 三个功能图标现在**每格带一个数**（≥110px 宽之后光放 34px 图标太空）：
  `图标 40 + 名字 12 + 数值 15/600 + 说明 11`，有分母的再配一条 3px 进度条
  （Bingo 点亮格数、远征本段格数），没有分母的不画条、内容垂直居中。
  顺序是 **卡片 → 三格 → 目标行**：目标是一行「输入」，夹在卡片与三格之间
  会把首屏切成「数据 / 表单 / 入口」三段。
- 目标本周是**一周一次**的动作，做成 **56px** 整行入口（左主文、右副文、末尾 ›），
  点开才是表单；不要混进「标签 + 内容」的 kv 表里当一行。48px 是个尴尬高度：
  既不是列表行 64，也不是按钮 44，夹在两档网格中间谁都不属于。
  副文 12（不是 11）：`已跑 38.1 / 30 km · 已达成` 或 `已跑 6.2 / 38.6 km · 16%`，
  未达成才报百分比；建议值口径写「近 4 周周均 × 0.8」，与服务端 `_suggest_goal` 一致。
- 一个人的组：**榜单照常渲染**（自己那一行也有里程和天数），只在后面补
  一句状态 + `邀请码 + 复制`。「第 1 名」对一个人没有信息量，改称「本周成绩」。
  曾经把整块榜换成空态，用户一进来看不到「本周榜」只剩一句提示，像页面坏了。
- 邀请码要能一键复制：走 WebView 的 `execCommand('copy')`（隐藏 textarea
  + 用户手势内同步执行），**不要为此加 Kotlin 桥**——加一个 JS 方法就要重打 APK。
  `navigator.clipboard` 在 `file://` 下不是安全上下文，只能当兜底。
- 页头胶囊只说一件新事：`全组 93.2 km 本周`。「N 人」已经在副标题里，
  不再放一枚抄同一句话的胶囊；一个人组里「全组」等于「我」，这枚胶囊直接不出现。
- 榜单行：56px 高、右列带单位（`42.3 km`，单位 11px `--ink-3`）、
  左边缘与区块标题**文字**对齐（`.flat` 缩进 11px）。
- **六件衫不要在这排图标里出现第二个入口**：核心数据卡的徽章行
  （`六件衫 N/6 ›`）已经是它的入口，同一屏两个去同一页的按钮 = 让人选「点哪个」。
  徽章行还说得出「我有几件」，比一个文字图标信息量大。
- 卡片的色块只给「六件衫」和名次分数，其余一律 `--surface` 平底。

## 7. 验收

跑 `tools/audit_ui.py`（360 / 390 / 430 三档 × 今日/历史/计划/我的），必须全绿：

- 无横向溢出；无 <11px 文字；可点元素 ≥40px；关键数值不被 ellipsis 截断。
- `--ink-3` 在卡片底 ≥4.5:1；主按钮文字 ≥4.5:1（值见 §3.1，可直接引用）。
- 字号白名单：`11 / 12 / 14 / 15 / 16 / 20 / 24 / 32`。
- 圆角白名单：`10 / 14 / 18 / 999`（<8px 的进度条/柱子豁免）。
- **白名单必须扫全部页面 CSS，不只 `ui.py`**：`ui.CSS`、`screen.SCREEN_CSS`、
  `aiui.CSS`、`eventui.CSS`、`runsui.CSS`。只查 `ui.py` 时，`screen.py` 里
  写的 13px 和 `eventui` 的 8/9/12px 圆角一直是漏网的。
- 发光配额：每页 ≤1 处带品牌色的 `box-shadow`；其余阴影必须是黑色。

人工验收（每页 2 分钟）：

1. 首屏 3 秒内能否说出「今天/这周怎么样」。
2. 关掉屏幕亮度到 30%，`--ink-3` 是否还读得清。
3. 页面里是否还有第二处发光。
4. 是否有半档字号或裸色值（搜 `#` 与 `px`）。

禁止清单：

- 每张卡片都加蓝色描边 + 辉光
- 大数字用渐变文字或外发光
- 同一屏出现 3 个以上 20px 以上的数字
- 用 emoji 当图标，或用字母块代替图标
- 10px 及以下文字；11.5 / 12.5 / 13.5 这类半档
- 把口径解释塞进数据卡片里

## 8. 边界与例外

- **远征页（`runsui.py`）**：插画与衬线字体属于独立叙事层，只共用色板与间距，不套组件。
- **活动长图 / 分享图**：可放宽到 16:9，字号允许 +2px，色板与圆角不变。
- **赛事页**：允许用赛事主色做一条 3px 顶部条，其余仍按本文。
- **原生壳**：开屏与底栏必须与 `--bg` / `--surface` 对齐，不能出现第三种黑。
- **阴影里的 rgba**：`box-shadow` 内的 `rgba(...)` 属于光学参数（光晕半径与
  强度），不受 P4「页面不写裸色」约束——每个光晕的透明度都是一个独立数值，
  硬拆成 token 会得到十几个 `--glow-08 / --glow-12 / --glow-36` 之类的名字。
  约束是：**阴影颜色只能是品牌蓝或黑色**，不得出现第三种色相。
- **地图 / 图表内的颜色**：`--map-shared`、`_month_bars` 的渐变等是「图上的
  数据」而非界面色，允许单列 token，但同样不得在页面 CSS 里写死。

## 9. 流程

- 视觉改动走 `dev/*` 分支，`main` 只接受合并。
- >5 个文件或 >300 行走 Gitee PR（见 `docs/协作流程.md`）。
- 涉及发版时，先报版本号与内容清单，确认后再动 `__init__.py`、`build.gradle.kts`、`selftest.py` 的发版守卫；发版只在 `main`。
- 本文与 `design.py` 同步改：不接受「文档一套、代码一套」。
- **本文与参考稿冲突时，以参考稿为准，并当轮回写本文。**
  先例：参考稿把区块标题做成 16px、今天行做成整行描边、页头不留收尾线，
  都和本文旧版相反。照参考稿改完不同步文档，就会变成「文档一套、代码一套」，
  下一轮评审必然判为偏离。

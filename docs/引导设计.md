> 配套文档：`docs/设计语言.md`（视觉规则）、`docs/交互树.md`（页面与路由）。
> 本文只管一件事：**用户第一次碰到某个功能时，怎么知道下一步该干什么**。

版本 v1.1 · 2026-11-23 · 状态：**第一批已落地**（今日页空态与口径折叠 /
我的页入口收敛 / 历史页空态 / 组页目标建议与玩法说明）；

## 0. 一句话

**引导不是弹窗，是把「下一步」放在数据旁边。**

RunnerCoach 的数据密度很高（恢复度、负荷、TRIMP、六件衫、Bingo、远征、赛事……），
但用户打开 App 的问题永远只有一个：**今天/这周，我现在该干什么。**
任何不能回答这个问题、又占着首屏的引导，都是负担。

## 1. 现状：不是没引导，是引导散在错误的位置

> 下表是 2026-11-23 改造前的诊断，保留作依据。改造后的落地状态见 §1.1。

以小组页（`garmin_cn/groupui.py`，`group_page` 829 行）为例，一屏里同时存在：


| 现象 | 用户读到的意思 | 真正该给的引导 |
| --- | --- | --- |
| 「75 分」无口径 | 75 是高还是低？ | 一句基线对比 + 一个「怎么算」折叠 |
| 「第 1 名」+ 1 人组 | 我和谁比？ | 不下名次，改「本周」，并给「邀请队友」 |
| 「定本周目标 · 建议 38.6 km」整行可点但无按钮 | 点了会发生什么？ | 主按钮「设为目标」，并写清依据 |
| 六件衫 6 个彩色圆点（`groupui.py` 780–841） | 这 6 个颜色什么意思？ | 只显示已获得的 1 件，其余虚线灰 + 「荣誉 1/6 ›」 |
| 榜单只有自己一行 + 半屏空白 | 页面是不是坏了？ | 行内空态：`只有你在跑 · 邀请队友一起上榜 →` |
| 964 天数据、同步时间、口径 | 和我要做的事无关 | 收到页脚，主屏只留结论与动作 |

结论：**引导应该长在数据卡里，不该单独占一块。** 凡是需要"教"的东西，
都可以变成"卡里多一行字 + 一个按钮"。

### 1.1 落地状态（2026-11-23）

| 位置 | 之前 | 现在 | 还差 |
|---|---|---|---|
| 今日页 | hero 结论没有口径，空数据只写一句「还没有活动记录」 | 新增「恢复度怎么算的」折叠；三种空态都带 44px 虚线行 + 可点动作 | 首周三件事未实现 |

## 2. 四条原则

### G1 首次只讲三件事

新装后首屏只回答：**今天练什么 · 为什么 · 点了会怎样**。
其余功能靠页面内可点入口逐步露出，**不做 5 页引导轮播**。

- 首屏出现第 4 个"新概念"就该砍（例：同时讲恢复度、负荷、TRIMP、赛事提醒 = 4 个）。
- 允许一次性的**行内提示条**（44px，虚线，可关闭），不允许遮罩层和全屏教程。
- 引导完成判据不是"看过"，而是"做过一次"：跑完一次 → 计划生成 → 目标设定。

### G2 建议要带依据，一键可落地

"建议 38.6 km"必须同时给出：**依据公式**（上周全员 33.9 km × 1.14 = 38.6）+ **执行按钮**。

- 只给建议不给动作 = 没给。
- 依据写在建议下方一行（12px `--ink-3`），**不超过 20 字**；
  完整公式收进「怎么算的 ↗」折叠。
- 动作必须一键完成，不要跳到设置页再让用户填一遍数字。

### G3 空状态即入口

没有数据的地方不留白，写清两件事：**为什么空** + **点这里能做什么**。
四种空态的处理见 §5；共同点：**每一个空态都必须有一个可点动作**。

### G4 渐进披露

主屏只留「结论 + 动作」，其余按三层收：

| 层 | 内容 | 位置 |
| --- | --- | --- |
| L1 结论 | 今天能不能练、这周差多少 | 首屏 hero |
| L2 依据 | 基线、上周对比、建议公式 | 结论卡内一行，或二级区 |
| L3 口径与明细 | TRIMP 定义、分数权重、历史明细 | `details.fold`「怎么算的」「查看明细」 |

展开是一次点击（原地展开），**不是一次页面跳转**。

## 3. 首次进入（First Run）

### 3.1 首屏结构（今日页，2026-11-23 实际）

```
页头（kicker TODAY / h1「今天该怎么练」/ 数据天数与同步时间胶囊）
hero：结论句（可以练，别加量）+ 恢复度 75 环
  ├ 依据一行：比近 28 天基线低 6
  ├ 今日建议：课表已调整 / 优先补觉 / 建议减量
  └ 「恢复度怎么算的」折叠（默认收起）
二级：负荷三格（7 天 592 / 长期 83.7 / 状态 +8.8）
二级：身体 2×2（睡眠 6.5h / HRV 79ms / 静息 53 / 体重 66.15kg）
三级：训练计划卡（整卡可点 → /plan） ← 首屏收口动作
```

**不做的事**：不放"欢迎使用 RunnerCoach"卡片、不放功能介绍、不弹权限申请连环。


### 3.2 权限与数据源

- 只在前置动作**真的要用**时才申请（要记录跑步 → 申请定位；要同步 → 申请健康数据）。
- 拒绝后的兜底必须写清：`不授权也能手动记录，只是没有配速和轨迹`。
- 未同步时**不显示 0 值假数据**，显示 `—` + 「去同步」（§4.15 行内空值）。

### 3.3 首周的三次成功

| 次序 | 目标 | 达成信号 |
| --- | --- | --- |
| 1 | 完成第一次记录 | 今日页出现一次真实跑量 |
| 2 | 设定一次周目标 | 目标卡从「未设定」变「进行中」 |
| 3 | 看到一次结论变化 | 恢复度/负荷因这次跑步而变 |

三次都达成后再露出小组、赛事、远征——**在那之前，这些入口降级为三级辅助区**。

## 4. 建议与目标（G2 的落地）

### 4.1 建议公式（必须外显）

**唯一来源是服务端 `server/groups.py::_suggest_goal`，客户端不另算一套。**

| 场景 | 公式 | 说明 |
| --- | --- | --- |
| 有近 4 周数据 | 近 4 周周均里程 × 0.8 | 目标是拿来达成的，按周均报会一跳就完不成 |
| 近 4 周为 0 | 不给建议（返回 0） | 不猜测，让用户自己填第一周 |
| 已定过目标 | 不再显示建议 | 建议只服务「还没定」的那一次 |

为什么不按「上周 × 1.14」：让分赛和预言都建立在目标上，目标定高了会让
「能不能达成」变成运气；0.8 是留出状态波动的余量。**文档不许写一套、代码算一套**——
用户拿页面上的数字心算，对不上就会觉得建议是编的。

显示格式固定：`还没定 · 建议 38.6 km（近 4 周周均 × 0.8）`，
序号保留 1 位小数，单位与数字之间留空格。

### 4.2 目标卡（小组页核心数据卡之下第一块）

**还没定目标、服务端也给了建议值时，收起态就是一个完整动作：**

```
┌──────────────────────────────────────────────┐
│ 定本周目标                                    │
│ 建议 38.6 km · 近 4 周周均 × 0.8   [设为目标] │
└──────────────────────────────────────────────┘
```

点「设为目标」直接 POST 建议值，不再展开表单、不用填数字。

**定了目标之后**，同一行变成折叠入口（改数字 / 改预言是低频动作）：

```
┌──────────────────────────────────────────────┐
│ 目标 38.6 km                                  │
│ 已跑 20.9 / 38.6 km · 54%                    › │
└──────────────────────────────────────────────┘
        ↓ 点开
[ 目标 km  38.6 ]  [ 预言  先不猜 ▾ ]
[ 保存 ]
```

规则：

1. **只有一个主动作**：没目标时是「设为目标」，有目标时是「保存」。不做
   "编辑 / 自定义 / 稍后"三个并列；目标框预填当前值，用户不改数字直接保存就是确认。
2. 设定后**就地替换**为进度态（不跳页、不弹 toast 就算完成）：
   入口行变成 `目标 38.6 km · 已跑 20.9 / 38.6 km · 54%`。
3. 达成后不再报百分比（`127%` 像出错），写 `已跑 41.2 / 38.6 km · 已达成`。
4. 周期写在表单上方一行：`11-16 – 11-22 · 周日 24:00 截止`。
   不知道截止时间，目标定多高、什么时候能改都没法判断。
5. 没有建议值（近 4 周为 0）时不摆一个注定要手填的空表单，退回折叠入口并
   在副文写「还没定」；用户点开自己填第一个目标。

## 5. 空状态即入口（G3 的落地）

| 类型 | 场景 | 文案（≤20 字） | 动作 |
| --- | --- | --- | --- |
| 首次无数据 | 新装、无历史 | 还没有跑步记录 | 开始第一次记录 |
| 筛选后为空 | 选"骑行"，本月无骑行 | 本月没有骑行 | 清除筛选 |
| 离线 / 未连数据源 | Keep 未连接 | 未连接 Keep，无法同步 | 去连接 |
| 行内空值 | 字段缺失 | — | 无（显示 `—`，不显示 `0`） |
| 1 人小组空榜 | 只有自己 | 只有你在跑 | 邀请队友一起上榜 |
| 空月份 | 2025-12 – 2026-06 | 7 个月无记录 | 展开 |

排版二选一（详见 `设计语言.md` §4.15）：

- **行内空态**（44px 虚线行，左文案右动作，class `.gaprow`）：用于"某一块空"。
- **卡内空态**（普通卡 + 标题 + ≤2 行说明 + 一个按钮）：用于"整块业务空"。

**落地位置（2026-11-23）**：

| 页面 | 空态 | 落点 |
| --- | --- | --- |
| 今日 · hero | 还没有今日数据 · 去连接数据源 | `.gaprow` → `/me` |
| 今日 · 最近活动 | 最近 7 天没有训练 · 看全部历史 / 还没有跑步记录 · 去连接数据源 | `.gaprow` → `/history` 或 `/me` |
| 历史 · 列表 | 筛选筛空 → 清除筛选；无记录 → 去连接 | `.gaprow` → `/history?mode=list` 或 `/me` |
| 小组 · 1 人榜 | 只有你在跑（榜单照常渲染 + 邀请码 + 复制） | `.note` + `.invrow` |

**禁止**：整屏居中插画、emoji 大图、"暂无数据"四个字结束、空态里放两个同级按钮。

## 6. 渐进披露的展开规则

1. 折叠入口统一 `details.fold`，44px，虚线，右箭头；展开动画 200ms（`--t-base`）。
2. **一个区块最多一个折叠**；两个折叠挨着就合并成一个「更多」。
3. 展开后**不改变页面高度锚点**：展开内容在折叠行下方，标题不动。
4. 口径类折叠标题固定三种说法：`怎么算的`、`数据从哪来`、`查看明细`。
5. 折叠状态不记忆（每次进入都收起）——口径是低频信息，没必要常开。

## 7. 文案模板

| 位置 | 模板 | 示例 |
| --- | --- | --- |
| 结论 | 判断 + 幅度 | 可以练，别加量 |
| 依据 | 对比 + 数字 | 比近 28 天基线低 6 |
| 动作 | 动词 + 时长/距离 | 开始 32 分钟轻松跑 |
| 建议 | 数字 + 出处 | 近 4 周周均 × 0.8，建议 38.6 km |
| 空态 | 为什么空 + 动作 | 本月没有骑行 · 清除筛选 |
| 失败 | 发生了什么 + 怎么办 | 同步失败，检查网络后重试 |

禁止：感叹号、卖萌语气（哦/啦/呀）、营销词（燃脂/暴汗）、
结论位用模糊词（可能/大概）、同一动作多种说法（设目标/定目标/立目标）。

## 8. 度量与验收

上线后按页面看四个数（**埋点还没做，这四个数现在取不到**；先加事件再谈效果）：

| 指标 | 口径 | 目标 |
| --- | --- | --- |
| 目标设定率 | 见过目标卡的用户中点了「设为目标」的比例 | ≥40% |
| 空态点击率 | 空态曝光后 30s 内点动作的比例 | ≥25% |
| 口径展开率 | 点开「怎么算的」的比例 | 5%–15% |
| 首周三件事完成率 | 记录 / 设目标 / 看到结论变化 全达成 | ≥30% |

验收（每屏 2 分钟）：

1. 首屏能否用一句话说出"我现在该干什么"。
2. 每个数值是否带单位与比较对象。
3. 每个空块是否有可点动作。
4. 是否只有一个主按钮；两个入口是否指向同一动作。
5. 折叠是否 >1 个挨在一起。

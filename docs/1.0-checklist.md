## 二、P0：不做完不能叫 1.0

### 1. 真机验证 v65 的两处改动（阻塞）

上一轮改了补全历史机制但没有真机反馈，这是当前最大的不确定项。

- [ ] 下拉刷新后标题栏出现「补齐历史 第 N 段：a ~ b（新拉 X 天）」
- [ ] 连刷几次，「我的 → 本地数据」的起始日期逐日往前推
- [ ] 补到 8 年前后，刷新不再有进度提示，且抓包确认零请求
- [ ] 弱网 / 断网下刷新不卡死、不弹「请重新登录」

验收：4 条全部符合，或把问题记进 issue 后修正。

### 2. 换成正式签名（不可逆，越早越好）

`android/app/build.gradle.kts` 里 `signingConfig = signingConfigs.getByName("debug")`。
debug 签名每台机器不同、Android 还限制其有效期，**一旦以后换签名，老用户无法覆盖安装，
只能卸载重装——而 `allowBackup=false`，等于历史全丢**。

- [ ] 生成 keystore，放项目外或 `android/` 下并加进 `.gitignore`（当前没有 `*.jks` / `*.keystore` 规则）
- [ ] `build.gradle.kts` 新增 `signingConfigs.release`，口令从 `local.properties` / 环境变量读，不写进仓库
- [ ] `release.py check` 增加一条：打正式版时若仍是 debug 签名直接报错
- [ ] 用新签名出一个包，验证能覆盖安装当前 debug 包（不能的话要提前告知用户卸载重装）

验收：`apksigner verify --print-certs` 显示的是自己的证书，且 `versionCode` 递增可覆盖升级。

### 3. 数据导出 / 导入（1.0 的底线）

现在换手机 = 8 年历史清零。README 说「数据不出本机」，那就更要给用户一个自己搬家的办法。

- [ ] 新增 `appapi.db_export()`：把 `data/garmin.db` + `data/photos` 清单打成 zip 到 `output/`
- [ ] App「我的 → 本地数据」加一行「导出数据」，走系统分享（复用现成的分享通道）
- [ ] 新增导入：选 zip → 校验表结构 → 备份旧库 → 覆盖（冲突时以 zip 为准）
- [ ] 桌面端补 `run.bat export` / `import`，与 App 同一实现

验收：A 机导出 → B 机导入 → 日汇总条数、活动条数、最近一条活动一致。

## 三、P1：1.0 前强烈建议

- [ ] **异常诊断导出**：`data/diag.log` 记录最近异常（时间 + 模块 + traceback 摘要），「我的」里一键复制。现在崩溃了用户只能描述「打不开」。
- [ ] **纯高驰用户的课表兜底**：`appapi.plan()` 无佳明会话时直接返回 `ok:false`，首页整块课表不显示。应回落到教练处方 / 备赛计划，别让高驰用户永远看不到「今天该怎么练」。
- [ ] **demo 数据自动重建**：`cli.py demo` 复用已有 `demo.db`，代码升级后新增字段看不到（本轮实测踩到：旧 db 的 `activity_detail` 是 0 行，活动图直接失败）。加一个 `SCHEMA_REV` 元信息，不一致就重建。
- [ ] **数据库版本化迁移**：引入 `PRAGMA user_version`，把现在的列探测包进 `migrate(conn, from, to)`，1.0 之后改表才有章法。
- [ ] **`server/` 处置**：要么移到独立仓库，要么在 README 与发布流程里明确「未启用、不参与分发、与 App 无关」，并在 `release.py` 的打包黑名单里排除它。现在源码包里带着一套支付/短信服务端，容易被误解成产品的一部分。
- [ ] **包名与商标风险**：`com.garmincoach.app` 与佳明商标高度关联。若只小范围分发，至少在 README 与「关于」里写清「个人自用工具、与 Garmin 无关联、不提供代登录」；若要公开发布，建议改包名与应用名。

功能面不需要再变大——现在这些已经够撑起 1.0。真正挡路的是签名、备份、诊断这三件「用久了才会痛」的事。

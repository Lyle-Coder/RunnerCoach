# 交付形态调研：怎么把这套东西给别人用

> 调研对象：RunnerCoach（佳明国区数据 → 每日看板 / 电子教练）
> 关注点：隐私不外泄、优先可断网、他人上手成本低
>
> 本文是设计决策记录，供协作者理解「为什么这样分发」。文中所有检查项均为通用规范，
> 不含任何真实账号、设备或健康数据。

---

## 一、结论先行

**推荐主形态：便携桌面版（本地运行 + 本地网页界面），配一个「纯离线导入模式」兜底。**

理由只有一条，但很硬：这套东西的全部价值来自「你自己的账号 + 你自己的数据」。
一旦搬到云上，就必须有人替你保管别人的佳明密码、睡眠、体重、GPS 轨迹——
这是敏感个人信息里最敏感的那一档，而且和佳明服务条款直接冲突（见 §5.4）。

三句话版本：

| 场景 | 用什么 |
|---|---|
| 给朋友长期用 | 便携桌面版 zip（双击 → 本地网页界面），数据只在他自己电脑上 |
| 给别人看一次结果 | 导出**脱敏**的自包含 HTML / PNG，微信发文件，双击就开，完全离线 |
| 手机上看 | 把 `latest.html` 发给自己，或同一 WiFi 下用局域网只读页；不做 App |

**不推荐**：微信小程序、云端网页（SaaS）、手机原生 App。三条都不符合"隐私 + 断网"，
且技术上要推翻重写（§3 有逐条拆解）。

## 二、先看清技术事实（这决定了能选什么）

| 事实 | 数值 / 说明 | 对交付形态的影响 |
|---|---|---|
| 代码规模 | 16,615 行 Python（不含测试脚本） | 重写成 JS/原生 App 是"重写项目"，不是"移植" |
| 第三方依赖 | **零**，纯标准库 | 打包极易，一个 Python 运行时就能带走 |
| 数据落点 | 本地 SQLite（`data/garmin.db`）+ JSON | 天然单机，没有服务端可言 |
| 看板产物 | 单个 HTML，**0 个外部请求**（已核实） | 可离线打开、可当邮件附件发、不依赖任何 CDN |
| 出图依赖 | PNG 需要本机 Chrome/Edge 无头；MP4 需要 ffmpeg | 打包体积 +80MB（ffmpeg 可选） |
| 大模型调用 | **代码里 0 处**（无任何 API key / HTTP 到模型服务） | 断网不影响核心功能，见 §4 |
| 网页快照 | `site/` 是本机产物目录，可能含真实看板 | 已加入 `.gitignore`；演示请用 `demo` 的仿真数据 |

关键判断：**这不是一个"网站"，是一个"本机工具 + 会自己生成本地网页"。**
它的正确交付物不是域名，是一个能双击的文件夹。

## 三、五种形态逐条比对

| # | 形态 | 断网可用 | 隐私风险 | 复用现有代码 | 他人上手 | 合规风险 | 结论 |
|---|---|---|---|---|---|---|---|
| 1 | **便携桌面版**（zip + exe/bat + 本地网页 UI） | ✅ 除同步外全离线 | **低**（数据只在他机器） | ~95% | 中（解压→双击→填账号） | 低-中 | **★ 主推** |
| 2 | **桌面壳**（Tauri / pywebview 包一层） | ✅ | 低 | ~95% | 低（像装了个软件） | 低-中 | 想要"像个 App"就选它 |
| 3 | **静态离线包**（自包含 HTML/PNG 导出） | ✅ 完全 | 极低（但文件本身=数据） | 100%（现有产物就是） | 极低（双击） | 无 | **★ 分享/备份** |
| 4 | **PWA + 文件导入**（纯前端重写） | ✅ 完全 | 极低 | ~40%（计算与出图要重写） | 极低（一个链接） | 无 | 备选，成本最高 |
| 5 | **微信小程序** | ❌ 必须后端 | **高** | ~10% | 低 | **高** | 不推荐 |
| 6 | **云网页 SaaS** | ❌ | **极高** | ~60% | 低 | **极高** | 不推荐 |
| 7 | **手机原生 App** | 部分 | 中 | ~15% | 低 | 高（资质+条款） | 不推荐 |

### 3.1 便携桌面版（推荐）

- **形态**：`garmin-coach-portable.zip` → 解压 → `启动.bat` → 浏览器自动打开 `127.0.0.1:8765` 的本地界面。
- **为什么好**：现有 16.6k 行一行都不用改逻辑，只需要加一个「本地 HTTP 壳 + 首页」；
  数据目录、SQLite、出图、回放全部照旧。
- **断网**：开机不联网也能看昨天的看板、算营养、出图、看回放；只有"同步"那一下要网。
- **打包**：Python 嵌入版（Windows embeddable，约 15MB）+ 代码，用户**不用装 Python**；
  ffmpeg 单独放可选包（80MB），不装就不出 MP4，其余功能不受影响。
- **代价**：Windows 优先。要跨 mac/Linux，得分别打三份（代码是跨平台的，主要是启动器和路径）。

### 3.2 桌面壳（如果想要"App 的感觉"）

- 用 **pywebview**（最轻，复用现有 Python 后端）或 **Tauri**（安装包小、界面现代，但要把 UI 重写成前端）。
- 收益主要是观感：有窗口、有图标、有托盘、能开机自启。
- 建议：**先用 1，觉得不够再套 2**。两者前端可以共用同一套本地 HTML，不冲突。

### 3.3 静态离线包（分享的正确姿势）

- 现有 `report` 产出的 HTML 已经是自包含的——**这就是最好的分享格式**。
- 需要补的只有一件事：`export --share` 做**脱敏导出**
  （去掉起终点、轨迹、精确时间、地点名，只留聚合指标与趋势）。
- 发微信文件即可，对方双击打开，不联网、不装任何东西、也不需要账号。

### 3.4 微信小程序：技术上就走不通

不是"麻烦"，是几个硬约束同时卡住：

1. **跑不了 Python**：没有解释器、没有 ffmpeg、没有无头浏览器 → 出图、回放、MP4 全废。
2. **连不上本机**：小程序禁止请求本机 IP（`127.0.0.1` 明确不允许），域名还必须 HTTPS + ICP 备案。
3. **连不上佳明**：`connect.garmin.cn` 不在你的白名单里，也过不了备案主体校验。
4. **只能走自建后端**：那就等于把所有用户的佳明账号密码、健康数据、轨迹集中到你的服务器上。
5. **条款冲突**：佳明服务条款明写 *"You must not share your account credentials with any third party"*
   （garmin.cn 同款）。让用户把密码填进你的小程序，就是在教用户违约。
6. **类目资质**：健康/医疗类小程序需要资质，个人主体基本过不了审。

**唯一勉强成立的用法**：把小程序做成"只读壳"，访问你家里电脑的局域网 IP。
但 IP 会变、必须同 WiFi 常开电脑、审核仍有类目问题——投入产出比极差。

### 3.5 云网页 SaaS：隐私与条款双杀

- 你从"工具作者"变成《个人信息保护法》下的"个人信息处理者"：
  敏感个人信息（健康、行踪轨迹）需要单独同意、影响评估、等保、隐私政策、数据删除通道。
- 佳明条款直接禁止代持凭据；逆向接口高频调用还会被限流封号，连累所有用户。
- 收益（省去安装）远小于风险（一次泄露 = 所有人的病历级数据）。

### 3.6 手机原生 App：投入最大，收益最小

- iOS 基本不可行：不能后台跑 Python、不能自由访问文件系统、不能调 ffmpeg。
- Android 可行但要重写全部计算与出图逻辑（16.6k 行 → Kotlin/Compose），
  上架还要软著、隐私合规、健康类目说明。
- 折中方案：Android 上用 Termux 跑现有 Python（等于给 1% 的用户准备的路）；
  或者干脆用 §6 的"手机看网页"。

### 4.5 大模型依赖到底有多少

**结论：只有 1 项真正依赖大模型——「教练点评的正文」。**

- 其余所有"看起来像 AI"的东西（今日处方、为什么这么练、风险提示、营养建议、简报结论）
  全是**规则引擎算出来的**，`coach.py` / `nutrition.py` / `brief.py` 里一行模型调用都没有。
- 点评是"外部写入、程序渲染"：MCP 工具 `garmin_save_note` 把文本存进 `notes` 表，
  `report` 再渲染。**没有大模型时，看板照常出，只是少一段自然语言。**
- 这意味着：**离线方案不会损失任何决策能力，只损失一段文字。**
  可以给用户一个开关：「AI 点评（需联网）/ 规则点评（离线）」，
  后者直接用 `coach.py` 里已有的结构化结论拼成段落，效果不会差太多。

## 五、分发前必须处理的隐私问题（按严重度排序）

### 5.1 🔴 P0：`config.json` 里是明文账号密码

```
{"email": "...@qq.com", "password": "....", "body_goal": "cut"}
```
- 它位于项目根目录，`.gitignore` 挡得住 git，**挡不住 zip 打包和截图**。
- 一旦把含凭据的项目文件夹原样发给别人，等于把佳明账号送出去。
- **改法**：
  1. 密码不落盘。登录成功后只留 `session.json`（会话 2 小时），过期就提示重新登录。
  2. 若一定要存（为了自动续期），用 Windows DPAPI（`CryptProtectData`，绑定当前用户）或 `keyring`，
     存到 `%LOCALAPPDATA%`，与代码目录分离。
  3. 打包含 `--reset` / 首次运行向导，强制清空 `data/` 与 `config.json`。
- **如果含凭据的目录曾经外发过，立即修改密码并重新登录。**

### 5.2 🔴 P0：不要把真实看板发布到公网

- `site/` 里的 `index.html` 是 `report` 生成的**真实看板**，含恢复度、睡眠、HRV、体重、体成分与课表。
- 任何把它注册成网页应用、传到静态托管或网盘分享的行为，都等于把健康档案挂在网上。
- **改法**：该目录已加入 `.gitignore`；要演示就用 `run.bat demo`（或 `./run.sh demo`）
  生成的仿真数据，并在页脚写明「示例数据」。若曾公开发布过真实看板，先下线再评估影响。

### 5.3 🟠 P1：`data/` 里全是等价于密码的东西

`session.json`（JWT_WEB + session）、`data/mi_auth.json`（passToken / ssecurity）、`mi_login.json`。
- 分发前必须让 `data/` 为空；打包脚本里加一步 `assert not (data/'session.json').exists()`。
- 文档里明说：「这个文件夹等同于你的密码，别发人、别传网盘」。

### 5.4 🟠 P1：不能做"代登录"的服务

佳明服务条款（含 garmin.cn）明确：*不得向任何第三方共享账号凭据*。
所以任何"你帮我填账号、我帮你拉数据"的形态（SaaS、小程序、公众号）都是**结构性违规**，
不是"注意一下就行"。本地运行是唯一站得住的姿势——凭据从头到尾没离开过用户自己的机器。

### 5.5 🟠 P1：轨迹 = 精确行踪

- 起点终点一连，基本等于家庭住址。现有代码已经做对了一半（只本地出图、不随看板上线）。
- **已落地（0.1.4）**：`garmin_cn/privacy.py` 提供 `none / trim / hide` 三档，纯标准库、
  零 IO，在生成 HTML 之前就把轨迹处理掉（出完 PNG 再打码是没用的，原始折线还留在
  `output/*.html` 里）。
  - 桌面：`run.bat act --card --privacy trim|hide`；App：点活动出图前弹单选确认，
    默认 `trim`，选择记在 `gc_prefs`。这一问同时充当「分享前确认」。
  - `trim` 用 haversine 累加几何距离裁首尾各 200 m；不够长就整条隐藏。
    `hide` 完全不画折线，也不叠高德底图/照片，连精确起跑时刻一起去掉。
  - 占位块尺寸与原轨迹卡一致（不用 `display:none`，否则 `.mid` 的 flex 会塌版）；
    产物文件名带 `-trim` / `-hide` 后缀，不和原图互相覆盖。
  - `run.bat selftest` 有硬断言：脱敏版 HTML 不得出现轨迹 path、起跑时刻或经纬度。
- **仍待办**：
  - 「家附近模糊化」：以常驻点为圆心 500 m 内的轨迹点抖动或裁掉（需先让用户设点）；
  - 轨迹回放 MP4 导出前复用同一档位并弹确认。

### 5.6 🟡 P2：高德 Key 与水印

- Key 绑定个人实名 + 5000 次/日配额，**不能内置进分发版**（会被刷爆、也违反高德条款）。
- 现状已经是对的：没有 Key 就回落矢量轨迹，功能不中断。保持这个设计，文档里教用户自己申请。
- 水印不能裁、底图不能存下来二次分发——README 已经写了，分发版要在首次使用高德时弹一次提示。

### 5.7 🟡 P2：日志与报错

- `doctor` / `debug-login` 会打印 Cookie **名字**（不含值），这个尺度可以，但要确保异常堆栈里
  不会带出 `Authorization`、`Cookie`、经纬度。
- 加一个 `--safe-log`：默认关闭详细日志，出问题时用户手动开。

## 六、推荐落地路线

### 阶段 1：能安全地给别人（改动很小）

1. 凭据改造（§5.1）：密码不落盘 + DPAPI/keyring。
2. `--profile <名字>`：一个程序管多个账号，数据各在各的目录（家庭/朋友场景够用）。
3. `garmin-coach.exe` 本地服务 + 首页：`127.0.0.1:8765`，只监听回环地址。
4. 首次运行向导：选数据目录 → 登录 → 跑 `demo` 给一张示例看板 → 再同步真实数据。
5. 打包脚本：Python 嵌入版 + 代码 + `启动.bat`，产出 `garmin-coach-portable-vX.zip`。

### 阶段 2：把"离线"做成卖点

1. **纯离线模式**：`import` 导入 FIT/GPX/CSV 或佳明「数据导出」包，完全不登录。
   → 这是唯一 100% 断网、100% 无凭据的路径，适合"只想看分析不想给账号"的人。
2. `export --share`：脱敏自包含 HTML（去轨迹、去地点、去精确时间）。
3. 规则点评兜底（§4.5），AI 点评变成可选增强。

### 阶段 3（可选）：观感升级

- pywebview / Tauri 套壳 → 真窗口、托盘、开机自启；
- 局域网只读页：`--lan` 起在 `0.0.0.0:8765`，手机同 WiFi 直接看，用完关掉；
- 想要跨端，再考虑 PWA 重写（成本最高，收益是"零安装"）。

## 七、给别人时 zip 里放什么

```
garmin-coach-portable/
├─ 启动.bat              ← 双击即用，自动开浏览器
├─ runtime/python.exe    ← 嵌入版，用户不用装 Python
├─ app/                  ← 现有代码（cli.py / garmin_cn / mcp_server.py）
├─ tools/ffmpeg.exe      ← 可选包，不进主包
├─ 使用说明.pdf / .html  ← 含"这个文件夹等同密码"的警告
└─ data/                 ← 空目录，首次运行才生成
```

几条硬规则：
- **不带 `config.json`、不带 `data/`、不带 `output/`**。
- 版本号写进 `启动.bat` 的标题栏，出问题好对版本。
- 不做静默自动更新（那等于在你的工具里开一个回连通道）；要更新就发新 zip，数据目录不动即可平滑升级。
- 每个 release 附一句"仅限个人自用，请勿代他人登录账号"。

## 八、手机上看，最省事的三种做法

| 做法 | 怎么做 | 断网 | 门槛 |
|---|---|---|---|
| 发文件给自己 | `latest.html` 用微信「文件传输助手」发到手机，浏览器打开 | ✅ | 极低 |
| 发图 | 一图流 PNG 直接发微信 | ✅ | 最低 |
| 局域网只读 | 电脑 `--lan` 起服务，手机访问 `http://电脑IP:8765/latest.html` | 需同 WiFi | 低 |

三种都不需要 App、不需要小程序、不需要服务器。日常"跑完看一眼"用第二种就够。

## 九、只用手机能不能用（iPhone 是分水岭）

先说结论：**能，但"同步"这一步必须有个能跑 Python 的地方。** 手机只当显示器，今天就能用；
要让手机自己完成同步，只有三种架构，而 iPhone 走不通其中两条。

| | 安卓 | iPhone | 需要额外硬件 | 手机端要装 | 数据落在 |
|---|---|---|---|---|---|
| A 手机自己当服务器（Termux） | ✅ | ❌ | 否 | 是（Termux + 一键脚本） | 手机里 |
| B 家里一台"数据中枢" | ✅ | ✅ | 是（闲置手机/笔记本/NAS） | 否 | 家里设备 |
| C 纯前端 PWA + 手动导入 | ✅ | ✅ | 否 | 否（加到主屏幕） | 手机浏览器 |
| D 不做客户端，做投递 | ✅ | ✅ | 是（任何一台电脑） | 否 | 跑的那台机器 |

### A. 手机自己当服务器（安卓 + Termux）——已落地

- 能力：同步、看板、简报、营养、回放 HTML 全都能跑；**PNG 出不来**（Termux 里没有能无头截图的
  Chromium）、**MP4 出不来**。但一图流本身就是 1080×1920 的 HTML——已经加了 `width=1080`
  视口声明，手机打开整张缩放贴合屏幕，截图发微信一样用。
- 日常形态：`Termux:Widget` 放一个图标，点一下跑 `sync + report`，再点浏览器。
- 门槛：一次性粘贴几条命令（可以做成 `curl … | bash` 的引导脚本）；后台被杀要在系统里放行电池优化。
- 适合：你自己、以及愿意折腾的朋友。**不适合长辈。**

**已实现的部分**（本轮改造）：

| 改动 | 文件 | 解决的问题 |
|---|---|---|
| `run.sh` | 新增 | 原来只有 `run.bat`，Termux 跑不了 |
| `setup-termux.sh` | 新增 | 一次装好 python/ffmpeg/termux-api + 桌面快捷方式 + `run.bat` 别名 |
| `daily.sh` | 新增 | 定时同步 + 出看板，带 `termux-wake-lock` |
| `sysopen.open_any()` | 新增 | `os.startfile` 在 POSIX 上不存在，`--open` 会 AttributeError；顺带让小蜜图形验证码能在相册里打开 |
| `card.can_shot()` + `cli._shot()` | 改 | 没有无头浏览器时不再报错退出，退化成 HTML 并给一句人话 |
| `auto_cards` 提前返回 | 改 | 否则每条活动都刷一行「找不到 Chrome」 |
| `doctor` 环境行 | 改 | 显示 Termux/Android，单独列「无头浏览器」并标明属预期 |
| `GARMIN_NO_BROWSER=1` | 改 | 强制跳过截图，用来定位慢在哪一步 |

仍未解决：MP4 导出（缺逐帧截图）、Termux 后台被杀（属系统行为，只能放行电池优化）。


### B. 家里一台"数据中枢"（最推荐给"没有电脑"的人）

- 设备：一台闲置安卓机、旧笔记本、NAS 或树莓派——只要长期插电、连 WiFi。
- 手机端：浏览器打开 `http://中枢IP:8765`，可以"添加到主屏幕"，图标点开就是看板。
- 在外面看：装 Tailscale（点对点加密，数据不经过任何第三方服务器）。
- **这才是"没有电脑使用条件"的正解**：他不需要会用电脑，只需要家里有个插座。
- 现成的一半已经做了：`run.bat serve --lan` 就是这个形态的查看端
  （只读、带访问码、令牌用 cookie 记住）。还缺：开机自启、定时同步、PIN 登录、PWA 图标。

### C. 纯前端 PWA + 手动导入（唯一真正零门槛）

- 打开链接 → 添加到主屏幕 → 拖入导出的数据文件 → 全部在浏览器里算 → 存 IndexedDB。
- 完全离线、不碰任何账号、可以公开分发。
- 代价：计算层（`metrics` / `coach` / `nutrition` / `body` / `brief`，约 3–4 千行）要移植到 JS；
  出图改 canvas；底图受 CORS 限制（高德静态图会污染 canvas，只能当背景不能导出）。
- **瓶颈不在技术，在入口**：手机导出佳明数据很别扭——手机浏览器要"请求桌面版网站"才能下载
  单条活动的 FIT/TCX/CSV；或者用 Apple 健康 / Health Connect 做全量导出（字段还缺恢复度和身体电量）。
  这一步不解决，PWA 就只是个"看板查看器"。

### D. 不做客户端，做投递

- 谁跑都行，结果发微信：一图流 PNG、`latest.html`、简报文本。
- 零开发、零风险，覆盖"只想看今天该怎么练"的需求。
- 唯一的坑还是那句：数据来自谁的账号，就得谁的本机跑。

### 排序建议

1. **先做 B**：改动最小（查看端已完成），安卓和 iPhone 都覆盖，朋友什么都不用装。
2. **再做 C**：等"手动导入"的入口被验证过（有人真的愿意每次导出），再投入重写。
3. **A 只给自己和极客朋友**，不做成产品。

### 一句实话

**同步这件事没法离线。** Garmin 的数据在云上，任何形态都要联网拉一次。
"断网可用"能保证的是"拉完之后的分析、出图、查看、发朋友圈"，不是"完全不需要网"。
真要做 100% 断网，只有 §6 阶段 2 的文件导入模式——那条路完全不碰账号。

## 十、一句话总结

**这个项目天生就该是"本机软件 + 本地网页"，而不是"网站"。**
把它做成小程序或 SaaS，等于为了省一次解压，把所有人的健康数据和佳明密码搬到一台必须 24 小时暴露在公网的机器上——技术上要重写，法律上是处理敏感个人信息，条款上直接违约。

守住"数据不出本机"这条线，剩下的都是打包问题。

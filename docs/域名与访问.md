### 1.3 主体与网站内容口径（**当前最大风险**）

已确认要按**个人主体**备案。这条和本项目功能直接冲突，必须先说清楚：

- 个人备案是「非经营性信息展示」，**严禁登录/注册、评论、论坛、社群、用户投稿**
  等交互功能（2026 年新规执行更严，多地管局直接驳回）。
- 本项目有账号体系、训练小组（动态/评论/赛事）、健康数据。**如果按实际功能
  报备，个人备案大概率过不了；即使侥幸通过，上线后被抽查也会被注销备案并封站。**
- 北京等严格地区还要求个人有本地户籍/居住证；**备案归属看你的身份证/居住证
  所在地，不看服务器在哪个地域**。服务器在 cn-beijing 不代表要报北京管局。

三条可选路径，按推荐排序：

| 路径 | 做法 | 代价 |
|---|---|---|
| **A. 转个体户/企业主体**（推荐） | 办个体工商户营业执照（线上可办），以个体户备案；登录、会员、小组都能解释为业务功能 | 办照 + 对公/税务，几天到两周 |
| B. 个人备案 + 缩减站点 | 只备案一个**纯展示**的静态站（训练记录介绍/下载页），App 的账号与小组不要挂在备案域名下 | 需要另给 App 找一个不备案的入口（境外域名/Tunnel），架构分叉 |
| C. 个人备案硬报实际功能 | 网站名称写「训练记录本」、不写社区/健康 | 高风险：初审可能过，管局/抽查大概率打回 |

**当前选择：C，先按个人提交试试。** 那就把「网站」和「App」分开看：

- `runnercoach.cn` 的**网站首页**做成纯静态介绍页（App 介绍、下载、隐私说明、
  备案号），**不放登录框、不放小组入口、不放评论区**。管局看到的是一个展示页。
- 账号、同步、小组这些是 **App 内的功能**，走 `/v1/*` 接口，不在网页导航里露出；
  App 本身按「移动应用备案」单独办，不和网站备案混在一起。
- 备案信息必须和网站实际内容一致：**不要**在方案书里写「有社区/论坛」，
  也不要在首页放这些东西。App 内保留功能不等于网站备案造假，但公开可浏览的
  网页必须干净。

**不要**为了过审把登录/小组藏起来再在网页上开放——这属于备案信息与实际不符，
是 2026 年重点清理的对象，代价比重新备案大。

域名注册人（WHOIS：李宇飞）必须和备案主体一致。



## 2. 备案流程（阿里云代备案）

1. 阿里云 App → 备案 → 新增备案 → 选「轻量应用服务器」→ 填备案服务号。
2. 主体信息：身份证正反面、手机号、邮箱；个体户/企业另加营业执照。
3. 网站信息：域名 `runnercoach.cn`、网站名称、服务内容、负责人。
   - 网站名称：`训练记录本`（5 个汉字；备选 `每日训练记录`）。个人备案不能用
     人物名称、地点、英文、纯数字，也不能含博客/论坛/社区/空间/主页/平台/
     资讯/作品展示等词——所以不能用「宇飞的运动记录」「RunnerCoach 运动记录」。
   - 网站内容：选「其他」（个人网站按官方要求选其他）。
   - 方案书/备注：个人使用的训练记录工具，不售卖、不投放广告、不提供医疗建议，
     网页只做 App 介绍与下载。
4. 阿里云初审（1–2 个工作日）→ 短信核验 → 管局审核（一般 7–20 个工作日）。
   初审可能打电话核验用途，按实际说：个人记录 + App 下载页，不对外经营。
5. 通过后拿到 **ICP 备案号**，按要求放在网站页脚（链接到 beian.miit.gov.cn）。
6. **公安联网备案**：网站上线后 30 日内到
   <https://www.beian.gov.cn> 做公安备案，拿到公安备案号也放页脚。
   这一步很多人漏掉，被查到会先提醒后处罚。

个人备案材料（2026 年）：

- 身份证正反面、本人手机号（非 170/171 虚拟号段）、邮箱；
- 实名域名证书（阿里云控制台可下载）；
- 人脸核验 + 真人实景拍照（阿里云 App）；
- 《网站建设方案书》+《内容合规承诺书》（2026-06 起多地要求）；
- 备案服务号。

个体户备案另加：营业执照、经营者身份证、经营范围需能解释网站内容。

**备案期间不要**把 `@`/`www` 解析到 `39.106.174.153`：未备案域名指向大陆 IP
会被拦截，而且备案审核期间站点应当不可访问。现在域名是 `clientHold`，
本来也解析不了，保持现状即可。

### 2.1 APP 备案是另一件事

网站 ICP 备案只管域名，**移动应用备案**（工信部 APP 备案）是独立流程，
要填 App 名称、包名、签名、服务器域名等，通过接入商/应用商店提交。
APK 自分发虽然不走应用商店，备案义务仍在；等网站备案下来再办，
两者主体和域名要对得上。

**两者是并列关系**：Aliyun 官方说明 App 备案不要求先做网站备案，但如果
`runnercoach.cn` 同时要打开网页，**网站备案也必须单独做**，否则网站有关闭风险。
App 备案成功后，备案里填的域名才允许访问阿里云内地资源。

#### 2.1.2 还需要补一份「网站备案」

App 备案只覆盖 App 后台域名，不覆盖网页。`runnercoach.cn` 首页要做静态介绍页，
所以还要在同一个阿里云账号下提交一份**网站备案**（主体、域名相同），
两边的域名和主体必须一致。顺序可以并行；网站备案下来之前不要把 A 记录指到服务器。


### 2.2 网站首页要放什么（备案后会被看）

个人备案的「网站」是一个**静态展示页**，不是 App 本身。最低内容：

- 站点标题：`训练记录本`（与备案名称一致）；
- 一句话：个人跑步/骑行训练记录工具，数据来自自己的运动设备；
- 3 条功能说明：每日看板、训练负荷、历史记录；
- 一个 App 下载入口（APK 或「内测请联系」）；
- 隐私说明：数据只存本机/服务器、如何删除；
- 联系方式（邮箱即可）；
- 页脚：`ICP 备案号` + 公安备案号（下来后补）。

**不要放**：登录框、注册入口、小组/评论/动态、任何 UGC 内容。
这些在 App 里，网页上不出现。

### 2.3 为什么「新增网站」入口不见了

阿里云同一个主体**同时只能有一个进行中的备案订单**。App 备案提交后，
「新增网站 / 增加网站」按钮会被隐藏，这是正常限制，不是账号问题。

两条路：

| 做法 | 操作 | 时间 |
|---|---|---|
| **A. 撤回重报（快，推荐）** | 订单还在「待审核 / 初审中」时，备案首页点「撤回修改」→ 重新备案 → 先填 App，再点「新增其它网站」把网站一起加进同一订单 | 一次管局审核，约 7–20 个工作日 |
| B. 等 App 审完再新增 | 不动当前订单，等 App 备案通过后，首页出现「增加网站」再提交 | App + 网站串行，约 2 倍时间 |

- 已提交到「管局审核」的订单**不能撤回**，只能走 B。
- 除湖北、湖南外，多数省份支持一个订单里同时备案多个网站/App；
  一个订单里 App 和网站各用一个备案服务号。
- 撤回不会罚款，只是重新排队；刚提交几分钟，重报成本最低。

### 3.2 安全组开 80/443

轻量应用服务器控制台 → 防火墙（如果是 ECS 则是安全组）入方向加：

- `80/tcp` 0.0.0.0/0（Let's Encrypt HTTP-01 验证 + HTTP 跳转）
- `443/tcp` 0.0.0.0/0（正式访问）

`8443` 保留（老版本 APK 还在直连它，别关）；`8088` 是 APK 下载，保留。

### 3.3 装 Caddy 做 TLS 终止 + 反代

Caddy 自动申请/续期 Let's Encrypt 证书，比 nginx + certbot 少一半配置。
源站 8443 是自签证书，反代时要跳过校验。

```bash
sudo apt-get update
sudo apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt-get update && sudo apt-get install -y caddy
```

`/etc/caddy/Caddyfile`：

```caddyfile
runnercoach.cn {
    encode gzip
    reverse_proxy https://127.0.0.1:8443 {
        transport http {
            tls_insecure_skip_verify
        }
        header_up X-Forwarded-Proto https
    }
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options nosniff
        Referrer-Policy strict-origin-when-cross-origin
    }
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl enable --now caddy
sudo systemctl reload caddy
curl -I https://runnercoach.cn
# 期望 200/404，证书由 Let's Encrypt 签发（不是自签）
```

如果 80 被占用/证书申请失败，看 `journalctl -u caddy -n 50`。Let's Encrypt
需要 80 能从公网访问到，备案没下来之前不要提前开。

### 3.4 更新服务端公开地址

服务端 `RC_PUBLIC_BASE` 现在应该还是 `https://39.106.174.153:8443`。
改成域名后，客户端拉到的 `platform_base`、APK 下载链接、分享链接才会走域名：

```bash
sudo systemctl cat runnercoach | grep -n RC_PUBLIC_BASE
# 编辑 unit 或 /etc/runnercoach.env，把值改成 https://runnercoach.cn
sudo systemctl daemon-reload
sudo systemctl restart runnercoach
```

老 APK 仍会先连内置的 `39.106.174.153:8443` 拉配置，拿到新地址后自动切域名；
不需要重打 APK。切换后保留 8443 至少一个版本周期。

## 7. 域名还能做什么

同一个域名不是只能开一个网页。按用途分子域最省事（同一主体、同一服务，
不新增独立网站内容就不必再备案一次；独立内容仍要按管局要求新增网站备案）：

| 用途 | 例子 | 说明 |
|---|---|---|
| 官网/介绍 | `runnercoach.cn` | 静态介绍 + 下载，已准备 `site/landing/` |
| App 后台 | `runnercoach.cn/v1/*` | 现在 8443 反代过去 |
| 下载 | `runnercoach.cn/apk/*` | 走 8088，只读 |
| 邮箱 | `admin@` / `no-reply@` | 收信用 MX，发信用 SMTP |
| 状态页 | `status.runnercoach.cn` | 可选，监控/维护公告 |
| 文档 | `docs.runnercoach.cn` | 可选，隐私说明/使用手册 |
| App Links | `/.well-known/assetlinks.json` | 安卓点链接直接进 App；等有分享链接再做 |

不建议：把 `api.` 单独暴露到公网再开一堆端口；也不建议自建邮件服务器。

### 7.1 用域名代替 QQ 邮箱发验证码

**可以，但域名本身不发信**：要有发信服务（SMTP/API），再把发件人换成
`no-reply@runnercoach.cn`。现在服务端用 `SMTP_HOST=smtp.qq.com` +
QQ 授权码，换掉只需要改 4 个环境变量。

推荐阿里云邮件推送（DirectMail，同一个账号）：

1. 控制台开通 DirectMail → 添加发信域名 `runnercoach.cn`；
2. 按控制台给的记录加 DNS：SPF（TXT）+ DKIM（CNAME），要收信再加 MX；
3. 创建发信地址 `no-reply@runnercoach.cn`，设置 SMTP 密码；
4. 改 `/etc/runnercoach/env`：

```ini
SMTP_HOST=smtpdm.aliyun.com
SMTP_PORT=465
SMTP_USER=no-reply@runnercoach.cn
SMTP_PASS=<DirectMail 的 SMTP 密码，不是登录密码>
SMTP_FROM=no-reply@runnercoach.cn
```

5. `systemctl restart runnercoach`，在 App 里发一次验证码验证。

注意：

- 免费额度每天 200 封，验证码够用；超出按量计费。
- **不要自建 Postfix**：阿里云默认封 25 端口，没有 PTR，送达率极差。
- 收信（`admin@runnercoach.cn`）和发信是两件事：只发验证码不需要 MX；
  要收信得开企业邮箱/邮件推送的收信能力，或把 MX 指到邮箱服务商。
- 加 DMARC（`_dmarc` TXT，先 `p=none`）能明显降低进垃圾箱的概率。
- 「服务认证」如果指第三方平台的联系人邮箱：域名邮箱可以填，但备案/认证
  本身仍看主体资料，换邮箱不改变认证结果；QQ 邮箱也能继续用。


## 8. 朋友通过域名访问，还差什么

先分清两种「访问」：

### A. 朋友装 Android APK（近期可行）

App 本身是本地优先，域名只承担账号、组、AI 代理和安装包。差这些：

1. **备案通过 + A 记录 + Caddy 启动**（当前等管局）；
2. `RC_PUBLIC_BASE` 从 IP:8443 切到 `https://runnercoach.cn`；
3. **邮件可达**：现在用 QQ SMTP，朋友用 QQ/163 一般能收到，Gmail/Outlook
   容易进垃圾箱；正式邀请前建议换 DirectMail + SPF/DKIM/DMARC；
4. **准入**：`/v1/auth` 目前是开放注册（FREE_GRANT 默认 0、AI_PROXY 默认 off，
   所以没有额度可薅，但任何人仍可建号）；要朋友限定就加邀请码/白名单；
5. **组邀请**：朋友注册 → 用邀请码进组 → App 上报每日汇总，这条链路要实测；
6. **APK 分发**：landing 页的下载链接要指向当前 APK，Android 需允许未知来源；
   发新版要同步改链接（或做 latest 软链）；
7. **端到端测试**：用 4G/别人的网络装 APK、注册、进组、同步、看榜；
8. **运维**：备份已有（03:20）、清理（04:10）、tick（5 分钟）；1.6G 无 swap，
   同时渲染重任务要串行；
9. **合规**：隐私说明、告知同意、账号删除（接口已有）、ICP/公安备案号；
10. **暴露面**：8443 继续给老 APK，443 给域名；SSH 只开密钥，管理接口
    必需 ADMIN_TOKEN，不要开 dev echo。

### B. 朋友用浏览器 / iPhone 打开（网页版 MVP 已实现）

`/app` 已经可以在服务器 `https://39.106.174.153:8443/app` 打开（自签证书会有
警告，域名备案后 Caddy 签 Let's Encrypt 就正常）：

- 邮箱验证码登录；
- 「我的 → 连接数据源」保存佳明/高驰账密（AES-GCM），后台串行同步；
- 今日、历史、按日看板、计划、赛事、我的；
- PWA manifest / service worker / 图标，可添加到主屏幕；
- 小组仍跳 `/w`（只读榜单/赛事/远征）。

还差/仍要注意：

1. 域名 + Caddy + 可信 HTTPS（等备案）；
2. 真实佳明账号的服务端登录/同步要真机验证；同 IP 多账号有风控风险；
3. AI 对话、活动图、推送、组内互动还没做；
4. 网页版数据在服务器，隐私说明与删除能力要同步更新。

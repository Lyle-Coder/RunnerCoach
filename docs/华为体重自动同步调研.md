# 华为体重同步

更新：2026-11-09。状态：**协议已验证，已接入，已入库出图**。

结论先说：华为这条线打通了，而且和小米一样是「云端读」，日常同步不需要手机参与。
三道闸门（账号 / 读体重 / 续期）全部实测通过，121 条真实体重已写入 `body` 表，
看板与一图流的体重来源已切到华为。

## 一、链路

```
秤 → 运动健康 App → 华为健康云 → huawei.py → body 表 → 看板 / 一图流 / AI
```

三家主机各管一件事（真机抓包确认）：

| 主机 | 用途 |
|---|---|
| `healthsession.things.dbankcloud.cn` | 会话：授权码换 token、refresh 续期 |
| `healthcommon.dbankcloud.cn` | 账号资料（uid、昵称、手机号） |
| `healthdata.dbankcloud.cn` | 健康数据，**体重在这里** |

原先推测的 `healthcloud.huawei.com` 是错的方向——该域名 NXDOMAIN，不存在。

## 二、认证：没有签名，只有 token + x-huid

这是整件事能成立的关键。业务请求不做签名，认证只靠两样：

- 请求体里的 `token`（一串 base64，来自会话接口的 `accessToken`）
- 请求头 `x-huid`（账号 uid）

其余字段（`deviceId`、`appId`、`rom`、`currentDeviceModel`）都只是设备与环境自述。
所以只要拿到一次 token，之后完全可以脱离 App。

### 三道闸门

**A 账号**：运动健康 App 用自己作为 OAuth 客户端（`client_id=10414141`）走华为账号
授权码登录，拿到 `authorizationCode` 后换会话：

```
POST healthsession.things.dbankcloud.cn/commonAbility/userAccessToken/obtain
{"authorizationCode":"<code>","appId":"10414141"}
→ {"accessToken":"…","refreshToken":"…","accessTokenExpireTime":<ms>,"uid":"…"}
```

密码模式（OAuth password grant）走不通——App 的 client_id 没有密码授权，
这是当初判断「大概率不行」的地方，实测确认。

**B 体重**：

```
POST healthdata.dbankcloud.cn/dataQuery/health/getHealthDataByVersion
{"type":10006,"version":"<游标>","token":"…", …}
```

- `type=10006` 是体重/体脂的数据类型号
- 数据在 `detailInfos[].samplePoints[]`，`key="WEIGHT_BODYFAT_BROAD"`
- `value` 是一段 JSON 字符串，`bodyWeight` 单位就是公斤
- 一次最多回 113 条，**用返回里的 `max(version)` 当游标翻页**，直到空

实测拉回 121 条（2026-07-05 → 2026-11-09），最新一条 71.15 kg 与 App 首页显示一致。

**C 续期**：

```
POST healthsession.things.dbankcloud.cn/commonAbility/userAccessToken/refresh
header: x-huid
{"refreshToken":"…","appId":"10414141"}
```

传错头会返回 `resultCode=20010004 Invalid x-huid header`，补上即可。
**实测 refreshToken 不轮换**，返回同一个 token 和同一个到期时间——意味着
我们续期不会把 App 自己的登录踢掉，两边可以共存。这是「首次授权后长期自动同步」
的前提。

## 三、用法

### 安卓账号登录入口（新增，待真机端到端验证）

「我的 → 华为体重 → 登录华为账号」在独立 WebView 打开华为账号页面，
账号密码和短信验证由华为处理。完成后拦截 `hms://redirect_url` 回调，校验
一次性 `state`（15 分钟有效），用 `code` 调用已有的 `userAccessToken/obtain`，
保存健康会话并自动拉取体重。日常自动同步需在体重偏好中选择「华为」。

这条入口沿用运动健康的客户端 ID，因此授权页面可能显示运动健康；
不是本项目独立注册的 Health Kit 应用。登录 WebView 不开放本地 JS 桥、文件访问或明文 HTTP。

2026-11-09 修正：上一版使用 `hms://redirect_uri`，虽然登录前参数检查通过，
但用户实际兑换健康会话失败，返回 HTTP 200 / `resultCode=20020001`。
用无效测试码调用健康接口得到相同错误，`resultDesc` 为 `invalid code`。

重新核对本地运动健康 APK（17.0.8.300）：

- `ThirdPartyLoginManager.thirdPartyPhoneLogin`：客户端 ID 来自
  `BuildConfig.HMS_APPLICATION_ID=10414141`，明确传入 **`hms://redirect_url`**。
- `ThirdPartyHttpUtils.postToGetAccessToken`：兑换请求体仍为 `authorizationCode` + `appId`，
  不需要在健康兑换接口额外传 `redirect_uri`。
- `ScopeManager` 与 HMS Lite `WebViewPresenter`：使用基础账号 scope
  `https://www.huawei.com/auth/account/base.profile`，并附加 `openid`、`nonce`、
  `ui_locales`、`include_granted_scopes=true`。本项目不照搬原 App 所有云盘、位置等权限。

已将 Python 授权 URL、回调校验和安卓拦截统一为正确回调，补充基础账号授权参数，
并为旧错误地址及授权码一次性解码添加回归测试。修正参数再次通过 `getLoginWay`，
返回 `isSuccess=true` 和华为 CAS 登录地址。
**回调不匹配是已确认的实现差异；是否解决 20020001，仍需用户在新版 APK 完成真实登录验证。**
如果仍然失败，继续检查授权范围和 SDK 环境参数，不应据此判断用户密码错误。
原来的抓包导入方式保留为 CLI 排查工具。

首次（只需一次）：

```bat
run.bat hw import --capture hw_capture.har      :: 从抓包提取会话
run.bat hw probe                                :: 三道闸门逐项体检
run.bat hw verify                               :: 真实拉一次，转正
```

日常：

```bat
run.bat body --huawei                  :: 手动拉一次入库
run.bat body --prefer-source huawei    :: 标记首选来源
run.bat report                         :: 出图前自动补拉（5 分钟节流）
```

`report` / `card` 会走 `live.scale()`，按「首选来源」决定拉哪家，所以切到华为之后
出图就是自动同步，和小米体验一致。

## 四、会话怎么来（三种，按可获得性排序）

1. **抓包提取**：`hw import --capture <HAR>`。有 obtain 响应就是完整会话
   （含 refreshToken）；只有业务请求也能救回 token，但没有续期能力。
2. **直接贴 JSON**：`hw import --json-file hw_session.json`，内容就是 obtain 的响应。
3. **授权码**：自己走一遍华为账号 OAuth，拿 `authorizationCode` 调 `obtain`。

抓包只用于**首次取会话**，不进入产品流程。抓包里含账号票据与真实体重，
`data/huawei_auth.json` 权限 0600 且不进版本控制。

## 六、踩过的坑（留给下次）

- **MuMu 不会被 adb 自动发现**，要 `adb connect 127.0.0.1:16384`。
- **MuMu 默认伪装成 HONOR**，华为运动健康据此走 EMUI 私有分支直接崩
  （`NoClassDefFoundError: WindowManagerEx`）。改成 Xiaomi 机型后正常。
- 官方 APK 直链：`https://appgallery.cloud.huawei.com/appdl/C10414141`；
  下载节点用 `appdl-drcn.dbankcdn.com`，`appdl-1-drcn` 那条握手会被重置。
- Git Bash 会把 adb 的远端 `/data/...` 转成本地路径，需要 `MSYS_NO_PATHCONV=1`。
- `mitmdump --set allow_hosts=a,b` 不生效（它是可重复的顶层参数），逗号串会导致
  全量隧道、看不到解密内容。

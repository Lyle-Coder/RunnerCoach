# 交互树（v2）

> 依据：**2026-11-23 main 分支的实际路由**（`garmin_cn/serve.py::_do_GET`）与原生返回逻辑
> （`android/app/src/main/java/mm/runnercoach/app/MainActivity.kt::nativeBack`）。
> 改 UI 前先对照这里；发现「文档写的和代码跑的不一样」时，先判断是哪一边错了，
> 再动代码——不允许只改一边。
>
> 配套文档：视觉规则见 [`设计语言.md`](设计语言.md)，引导与文案见 [`引导设计.md`](引导设计.md)。

## 一、六条硬规则

1. **一级导航只有底部 5 个 tab**：今日 / 教练 / 小组 / 历史 / 我的。
   页面内部不再出现指向其它 tab 的链接（`/groups`、`/me` 同理：小组是 tab，不是「我的」里的一个工具）。
2. **一个动作只有一个入口**（见 §4）。新增入口前先想清楚要不要合并。
3. **二级页逐级上退**，返回的是「上一级」，不是「所属 tab 的根」。
   在 `/groups/1/map` 按返回回 `/groups/1`，不是回「今日」。
4. **浮层（抽屉 / 弹窗 / 展开区）不进入历史栈**：返回键先关浮层，再谈页面。
5. **同页参数变化用 `replace`**（日期、筛选、分页，页面里写 `data-nopush`），
   不往历史栈里堆条目。
6. **写操作一律 POST + 303 回跳**，提示用 `?msg=` 带回并落在**发生动作的那个区块**
   （`?at=chal` 等），不换页、不弹全屏结果页。

## 三、返回键

优先级从高到低，命中即停：

| 当前状态 | 返回行为 |
|---|---|
| 页面浮层打开（`window.__gcBack()` 返回 `true`） | 关浮层，页面不动 |
| `/groups/{id}/xxx`（含 map / shirts / bingo / settings / audit / board / challenge / route） | 回 `/groups/{id}` |
| `/groups/{id}` | 回 `/groups?list=1`（带 `list=1`，否则单组用户会被直达弹回同一个组） |
| `/groups` | 回「今日」 |
| `/run` | 回 `/groups/{gid}`（`gid` 来自查询参数） |
| `/account` | 从小组进来回 `/groups`，否则回「我的」（链接带 `?from=groups` 时保留来源） |
| `/view` | 回「历史」；带 `from=today` 回「今日」 |
| `/plan`、`/plan/edit`、`/plan/draft` | 回「今日」 |
| `/training` | 回 `/plan` |
| `/event?slug=…` | 回 `/event` |
| `/event`、`/posture` | 回「教练」 |
| `/files`、`/privacy`、`/sports` | 回「我的」 |
| 在 `/ai`、`/groups`、`/history`、`/me` | 回「今日」 |
| 在 `/` | 退出 App |

实现方式：

- 页面暴露 `window.__gcBack()` 处理自己的浮层，返回 `true` 表示已消费；
  原生只在它返回 `false` 时才做页面级回退。
- **不使用 `web.canGoBack()` 当唯一依据**，否则切 tab、翻日期都会在历史栈里来回跳。
- 原生侧 `isTabRoot()` 负责在进入 tab 根页时清历史栈；**`/groups` 目前还不在
  这个列表里**（`/`、`/history`、`/ai`、`/me` 在），见 §7 待修项。

## 六、提示、锚点与状态

- **写操作**：POST → 303 → `?msg=…`；提示渲染在页首，除非带 `at=`。
  - `?at=chal`：提示落在组页赛事区块（在页面中部点「建赛事」的人看不到页首提示）。
  - `?focus=<aid>`：评论发完回来，展开那条动态的评论区。
  - `?feed=N#feed`：动态「继续往下看」，锚回动态区。
- **筛选 / 翻页 / 日期**：`data-nopush`（`history.replaceState`），返回键不按次数增加。
- **自动同步**：今日页加载 2.2 秒后调 `/__sync/today`；有新增 → 顶部胶囊提示并刷新；
  需要重登 → 点名数据源并给 `/me` 链接；其余静默。10 分钟节流，失败清戳下次再试。
- **数据过期**：今日页页头把「上次同步」换成「数据截至 MM/DD · 下拉同步」。
- **空值**：统一显示 `—`，不显示 `0`，不留空白（设计语言 §4.15）。

## 七、现状与规范的差距

> 这一节是「下一轮改什么」的清单，不是规范。修完一项就删一项。
> 标 **[P]** 的需要重打 APK（动 `android/`）；其余改 Python 后发代码包即可。

| # | 差距 | 影响 | 位置 |
|---|---|---|---|
| 1 | **`/groups` 不在 `isTabRoot()` 里** [P] | 切到小组 tab 后历史栈不清，长按返回可能退到上一个 tab 的旧页面 | `MainActivity.kt` `isTabRoot` |
| 2 | 计划页没有「完成今日课次 / 跳过」主 CTA | hero 结论说完没有落点，只能去编辑课表（设计语言 §5 计划、引导设计 §9） | `ui.plan_page` / `_today_plan_card` |
| 3 | 图标仍是 emoji 与字母块（G/C/K、⚙、◈、⌖…） | 同一屏 3–5 种画法；`icons.py` 已建但只落了 bell / bell-off | `ui.py`、`groupui.py`、`screen.py` |
| 4 | 模型服务有两条入口 | 违反「一个动作一个入口」，但目前是「状态行 + 设置抽屉」的合理分工 | `ui.me_page` |
| 5 | 历史页筛选折叠在列表**之后** | 首屏看不到筛选，用户以为只能翻页 | `history.history_page` |
| 6 | 首次引导未实现（首周三件事、埋点） | 新装用户不知道先连数据源还是先跑 | `引导设计.md` §3、§8 |

## 九、维护规则

1. 新增页面 = 同时改三处：`serve.py` 路由、本文 §2/§3、`nativeBack()`。
   只加路由不改返回，用户按返回就会掉到「今日」。
2. 新增入口 = 先查 §4 是否已有同类；有就合并，没有才加，并登记进表。
3. 新增浮层 = 在 §5 登记，并给页面补 `window.__gcBack()` 分支。
4. 写操作 = POST + 303 + `msg`；不允许 GET 改状态。
5. 本文与代码冲突时，**以代码为准先修文档，再判断代码是否偏离设计语言**；
   代码需要改的记进 §7，不要只改文档把问题藏起来。
